# Общая история и защита от повторных контактов

## Хранилище

Канонический файл — `iamkurakov/centrdb-data/work/patient-workspace.json`, приватный репозиторий. Схема `centrdb-workspace` версии 2 расширяет версию 1 без удаления прежних `patients`, `contacts`, `feedback`.

- `patients[id]`: версия рабочей карточки и результаты по направлениям.
- `assignments[id]`: один ответственный для всех направлений.
- `contacts`: добавляемая история результатов контактов.
- `feedback`: общие замечания по сценариям.
- `events`: журнал назначений, передач, сохранений, доступов и миграций с уникальным ID операции.
- `managers`: имена, роли и активность именных доступов.
- `migrations`: результаты однократного переноса записей устройств.
- `scripts[direction:variant]`: общий текст сценария, версия, автор и время изменения. Поле совместимо добавляется при первом редактировании.

Все операции читают свежий файл и записывают его с текущим blob SHA. GitHub отвергает устаревшую запись. При изменении другого ID операция переносится на свежую версию; при изменении этой же карточки нужна сверка менеджером. Один ID не может успешно закрепиться за двумя менеджерами из параллельных чтений. Автоматической перезаписи последней версией без объединения нет.

Уникальный ID операции остаётся прежним при повторе после неполученного подтверждения. Ответ, потерянный после успешного коммита, сверяется с журналом; история не создаётся дважды. Ошибка или отказ доступа не показываются как успешное сохранение. Локального режима записи после отказа облака нет.

## Назначения

Закрепление постоянно, пока сотрудник или руководитель его явно не освободит/передаст. Закрытие вкладки не освобождает ID. Результат разговора не передаёт ID в чужую очередь автоматически.

Общий запрет на связь учитывается во всех направлениях. Новый ответственный не берёт освобождённый ID в течение 24 часов после последнего контакта и до действующей согласованной даты из текущей рабочей записи. Устаревшие даты из исторических записей не блокируют новые договорённости. Руководитель может явно передать ID, видя предупреждение о контакте. Программа не совершает звонков и не может ограничить звонки вне интерфейса.

## Именные доступы без отдельного сервера

Как в принятом подходе «Идеал Сервис», GitHub Pages остаётся статическим сайтом, GitHub API хранит общие данные. Владелец один раз подключает ограниченный технический токен к `centrdb-data`. Для каждого сотрудника создаётся отдельный зашифрованный пакет: токен + ID сотрудника. Пакет передаётся в личной ссылке во фрагменте URL после `#`; он не уходит серверу Pages в HTTP-запросе. Пароль открывает пакет через PBKDF2-SHA256 (600 000 итераций) и AES-GCM. Пароль и открытый токен не публикуются в исходниках.

Доступы регистрируются в приватном рабочем файле. Перед чтением/изменением приложение проверяет активность сотрудника; роли и авторство берутся из реестра. При выбранном сохранении входа расшифрованное подключение живёт в sessionStorage данной вкладки. Личная ссылка остаётся на устройстве в зашифрованном виде; обычная работа не просит API-ключ.

Это не серверная изоляция прав: вошедший браузер получает общий ограниченный токен репозитория. Роли и отключение именного доступа проверяются приложением. Пользователь с извлечённым токеном технически может обратиться к GitHub напрямую. Для отзыва такого подключения владелец отзывает токен в GitHub и переиздаёт ссылки. Не используйте токен с доступом к другим репозиториям или административными разрешениями. Секреты другого проекта не используются.

## Перенос и актуальность

Переносятся только существующие записи прежнего `centrdb-coded-workspace`, по тем же постоянным ID. Демонстрационные записи из других баз не загружаются. Текущая общая карточка и назначение не затираются локальными; конфликтующие ID показываются числом для сверки. Контакты и замечания добавляются с проверкой ID. Исходная локальная база сохраняется.

Общее состояние перечитывается каждые 15 секунд и при возвращении во вкладку; любая запись повторно читает свежее состояние независимо от таймера. Аналитическая база RFM по-прежнему обновляется согласованной выгрузкой из 1С.

## Проверки

18 целевых тестов: конкурентный захват одного ID четырьмя менеджерами; непересекающиеся очереди; глобальное назначение; объединение разных ID; отказ устаревшей карточке; потерянный ответ после коммита; отказ в записи; запреты связи; согласованная дата; передача и отключение; миграция; большой raw-файл и замечания; криптографические именные ссылки; сохранение сценариев без изменения карточек и доступов; объединение разных вариантов; конфликт общей версии; ограничения и отказ в записи; потеря подтверждения и совместимость прежнего рабочего файла. Две тестовые сессии браузера проверяют видимость назначения и истории и запрет сохранения чужой карточки. Производственные пациенты, токены и личные пароли в тестах не используются.

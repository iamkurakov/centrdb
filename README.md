# ЦДБ — три раздела системы

Главная: три крупные текстовые ссылки. `economics.html` сохраняет подробную экономику. `marketing.html` содержит трёхмесячный план, результаты первого слоя и условия открытия следующих. `clients.html` — исходные агрегаты RFM и локальную рабочую базу с импортом.

## Хранение

- Экономика и сводные исторические сегменты опубликованы в GitHub Pages, как и предыдущая версия отчёта.
- Маркетинговые поля и групповые чек-листы сохраняются в localStorage этого браузера.
- Индивидуальные записи клиентской базы сохраняются в IndexedDB этого браузера. Они не отправляются на GitHub или сервер.
- Для переноса между устройствами есть экспорт и импорт JSON. Это не общая база для нескольких сотрудников. Данные могут быть потеряны при очистке браузера; сохранять выгрузки.
- Новая загрузка CSV/массива JSON заменяет срез, сохраняет результаты контакта по совпавшим кодам и сбрасывает групповые чек-листы. Импорт рабочей JSON-копии восстанавливает её собственные чек-листы и результаты.

## Клиентская база

По умолчанию показаны восемь агрегированных групп из отчёта на 21.10.2026. Исходные 994 карточки не опубликованы. Обновление происходит при локальной загрузке JSON/CSV, автоматической синхронизации с 1С нет.

Минимальные поля: `id`, `lastActivity` (YYYY-MM-DD), `purchases`, `amount`, опционально `remaining`. Код — внутренний обезличенный идентификатор. Не использовать телефоны как коды, не загружать ФИО, контакты или медицинские карты. В хранилище записываются только перечисленные поля. Период покупок и оплат должен быть одинаковым для всех записей. Правила баллов и округления FM описаны на странице.

Права доступа и разделение по сотрудникам — отдельный этап. На этом этапе нет авторизации, токенов или скрытых разделов.

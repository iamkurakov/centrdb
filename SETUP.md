# Первое подключение

Открыть marketing.html или clients.html. Ввести имя сотрудника и его действующий ключ GitHub с доступом к iamkurakov/centrdb-data и разрешением Contents: Read and write. Для рабочего места владельца подходит fine-grained PAT с выбором только этого репозитория. Не передавать персональный токен владельца другим людям. Права пользователей на репозиторий настраиваются в GitHub отдельно.

Ключ не передавать в чат и не добавлять в исходники. Ввод — в поле сайта либо через защищённую форму browserAuth. По выбору подключение сохраняется в sessionStorage вкладки и восстанавливается при перезагрузке. Отключиться очищает его. Простого входа по произвольному паролю центра без внешней системы авторизации здесь нет.

После подключения пациенты и история загружаются сами. Результат сохраняется кнопкой в карточке. Успех показывается только после подтверждения GitHub. Данные других рабочих мест обновляются примерно раз в минуту. При конфликте карточки текст остаётся в форме. Изменения другого пациента перечитываются и объединяются, максимум три попытки.

Демо и прежние локальные записи доступны через свёрнутый раздел на странице входа. Они отделены от общей базы и не изменяют её. Роли внутри приложения не разграничиваются: участник с доступом к репозиторию технически читает его файлы.

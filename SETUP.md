# Подключение общей работы

## Один раз: владелец

1. Открыть https://iamkurakov.github.io/centrdb/cloud-setup.html.
2. В своём браузере ввести ограниченный GitHub-токен только для закрытого `iamkurakov/centrdb-data`, разрешение Repository permissions / Contents: Read and write. Доступ к публичному репозиторию сайта не требуется. Не передавать токен в чат и не добавлять его в исходники.
3. Задать имя и личный пароль руководителя. При необходимости заполнить до четырёх менеджеров, каждому свой пароль от 12 символов.
4. Создать доступы. Сохранить выданные именные ссылки и передать сотрудникам их ссылку и пароль. Пароли не записываются в общую историю и повторно не показываются.

После входа руководителя доступы можно добавлять и отключать на той же странице без повторного ввода технического ключа. При отключении сотрудника его ID сохраняют прежнего ответственного, пока руководитель явно не передаст их.

## Менеджер

Открыть личную ссылку и ввести свой пароль. При выборе «Сохранять вход в этой вкладке» сеанс продолжается при переходах между разделами. Имя в истории берётся из выданного доступа, а не вводится заново при каждом звонке.

Выбрать направление → взять свободный ID или очередь из 20 ID → найти контакт в 1С → провести разговор → сохранить результат в общую историю. До закрепления ID и при занятом коллегой ID сохранение недоступно. Нельзя звонить по устаревшему списку при сообщении о потере общей связи.

Последний контакт, ответственный и история видны всем вошедшим менеджерам. Результат считается сохранённым только после подтверждения GitHub. Если ответ потерялся, повторить сохранение, не закрывая форму: идентификатор операции предотвращает дубликат. При конфликте карточки сравнить историю и явно продолжить с актуальной версией.

Прежние локальные записи переносятся автоматически при первом входе. Общие записи имеют приоритет при конфликте; локальные копии не удаляются. До технического подключения назначения и частная история недоступны, рабочие записи не создаются локально.

## Смена технического подключения

При истечении или отзыве GitHub-токена владелец подключает действующий ограниченный токен и выдаёт новые личные ссылки. Смена пароля/отключение именного доступа в интерфейсе не отзывает ранее расшифрованный GitHub-токен. Подробности — `SHARED_WORK.md`.

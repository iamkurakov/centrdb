# Подключение ЦДБ

## Публикация интерфейса

GitHub → iamkurakov/centrdb → Settings → Pages → Deploy from a branch → main → /(root) → Save.

Или на авторизованном компьютере владельца в PowerShell:

```powershell
& "C:\Program Files\GitHub CLI\gh.exe" api --method POST repos/iamkurakov/centrdb/pages -f "source[branch]=main" -f "source[path]=/"
```

Если Pages уже включён, повторно создавать его не нужно. Адрес после успешной публикации: https://iamkurakov.github.io/centrdb/ . Сборка GitHub Pages может занять несколько минут. Настройки Pages недоступны подключённому инструменту этого чата; эта команда выполняется на компьютере владельца.

## Персональный доступ владельца

1. Открыть https://github.com/settings/personal-access-tokens/new .
2. Название: `CDB browser`. Указать короткий срок действия, например 30 дней.
3. Resource owner: `iamkurakov`.
4. Repository access: Only select repositories → `centrdb-data`.
5. Repository permissions: Contents → Read and write. Metadata → Read-only добавляется автоматически. Остальные разрешения не выдавать.
6. Создать токен и вставить только в поле «Персональный токен GitHub» на странице приложения. Не отправлять токен в чат, не добавлять в исходники.

GitHub CLI уже авторизован на компьютере, но сайт не получает его авторизацию. Нужен отдельный ограниченный токен для браузера. Не копировать в сайт широкий токен из `gh auth token`.

Токен используется в памяти вкладки. После перезагрузки или отключения его нужно ввести снова. Истечение токена не удаляет данные. Сайт использует только GitHub API; дополнительных внешних скриптов на основной странице нет.

## Границы доступа

Эта версия — закрытое пространство руководства. Участники `centrdb-data` технически могут читать все файлы репозитория. Локальное скрытие разделов не ограничивает этот доступ. Не добавлять подрядчиков или администраторов в финансовый репозиторий ради доступа к одной инструкции.

Инструкции без конфиденциальных данных доступны без подключения. Для рабочей команды и подрядчиков нужны отдельные репозитории с отдельными наборами разрешений. Простого входа по логину центра и независимых четырёх ролей без посредника здесь нет. Для доступа внешних участников ограничения типов токенов нужно проверять отдельно; не передавать им токен владельца.

## Файлы и сохранение

- `reports/working-report.html` — рабочий финансовый отчёт в закрытом репозитории.
- `workspace.json` — общие задачи участников этого репозитория.
- `model-assumptions.json` — ограничения модели и вместимость центра. Автоматического пересчёта отчёта из этого файла в этой версии нет.

Задача сохраняется отдельным коммитом после добавления или изменения статуса. При конфликте параллельных изменений приложение не перезаписывает чужой результат: нажать «Обновить», повторить своё изменение. Несохранённое название новой задачи остаётся в поле ввода. GitHub хранит историю; это не полноценная CRM или высокочастотная база.

Не вносить в задачи телефоны, ФИО и сведения о здоровье пациентов. Исходные клиентские XLS в репозитории не загружены.
